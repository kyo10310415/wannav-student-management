# Discord未返信アラート

## DB登録失敗からの復旧

生徒投稿をINSERTするパラメータはメッセージIDをtextとして統一し、順序比較時のみtextからnumericに変換する。同じパラメータのtext/numeric推論が衝突するPostgreSQL 42P08を防ぐ。

履歴復旧・投稿処理で失敗したチャンネルは未処理位置を保持し、後続のイベントより先に再取得する。5分ごとの通知チェックでも最大10チャンネルずつ再試行し、継続して失敗するチャンネルは末尾へ回す。成功時は`[DiscordReplyMonitor] Recovery succeeded:`を記録する。本文・Webhook・認証情報はログに出さない。

再起動後はDBに保存済みの読み取り位置から復旧する。障害前のコードが読み取り位置を進めてしまった過去投稿や、初回監視開始より古い投稿を無断で遡って通知することはしない。対象投稿がその範囲にある場合は、本番DBの登録・解除・通知状態を確認したうえで個別復旧が必要。実Discordへの通知や本番DBの操作はテストでは行わない。

既存BotのGatewayイベントで監視し、返信待ちの投稿ID・日時をPostgreSQLに保存する。本文・添付ファイルは保存しない。初回導入前の投稿は通知対象にしない。

## 通知ON/OFF・AIチャットボット宛ての除外

- 管理者がユーザー管理画面のDiscord設定欄にある「未返信通知」のチェックを切り替える。OFFはそのTutorの担当生徒について、Tutor本人宛てと管理用チャンネル宛ての両方を停止する。他のDiscord通知・レッスンリマインドには影響しない。既存ユーザーは初期ON。
- 担当Tutorが空欄、登録ユーザーと紐づかない、紐づけが複数候補、契約解除の場合は一律通知しない。DiscordユーザーIDやWebhookのみ未設定の場合、ONかつ担当者が特定できれば従来どおり管理側には通知し、Tutor側は設定不足として保留する。
- 生徒投稿の登録時、通知候補処理時、履歴・リアクション確認の直後にDBの最新担当・通知設定を確認する（1時間キャッシュした設定では通知を決めない）。読み取りに失敗した場合は送らず保留する。OFFや担当未設定として処理した投稿は解除済みにし、ONへ戻してもその投稿を自動で再通知しない。過去の送信済み通知は削除しない。
- Renderの環境変数`DISCORD_REPLY_AI_BOT_IDS`にAIチャットボットの**ユーザーID**を登録する。複数はカンマ区切り。Botトークン・アプリID・チャンネルIDではない。未設定なら除外しない。
- 登録Botへのメンション、または登録Botが投稿したメッセージへの返信だけを除外する。通常投稿・スタッフへのメンション/返信・未登録Bot宛ての質問は勝手に除外しない。Botの自動投稿だけで他の未返信投稿を解除することもない。参照メッセージ取得に失敗した場合は推測して通知せず保留する。
- 通知直前にも最新の対象投稿を確認するため、既に待機中の投稿にもBot宛て除外を適用する。Bot宛ての投稿はその投稿のみ解除し、それ以前の通常質問は解除しない。
- migration 59で`users.discord_reply_alerts_enabled BOOLEAN NOT NULL DEFAULT TRUE`を追加する。通常のデプロイのmigrationを適用してから画面/APIを使う。既存のDiscord認証情報・予約URLは更新しない。

- 生徒のユーザーID・通常チャンネルは一斉送信と同じスプレッドシートから取得する。生徒・Tutor・スタッフの対応表は1時間キャッシュする。
- 生徒の全投稿を対象とし、夜間・休日を含む12時間経過後、5分間隔のチェックで通知する。追加投稿は既存投稿の期限を延長しない。
- ユーザー管理に登録済みのスタッフ（契約解除を除く）の通常投稿は、同じチャンネルのそれ以前の返信待ちを解除する。スタッフ判別にはDiscordユーザーIDの登録が必要。Bot投稿は解除しない。
- リアクションは付いた投稿だけを解除する。誰のリアクションでも対象。削除された投稿も解除する。
- 通知直前の単一メッセージ取得は`force: true`で古いDiscord.jsキャッシュを迂回し、最新のリアクション状態を確認する。`cache: false`だけでは既存キャッシュを迂回できない。取得失敗時は通知せず保留する。既に送信した通知を自動削除することはない。
- 担当Tutorにはユーザー管理のDiscord Webhookへ本人メンション付き、管理用チャンネル `1557730694166351912` にはロール `1294923221107478571` のメンション付きで通知する。Tutor設定が不足した場合も管理側へ通知し、Tutor側は設定修復後に再試行する。
- 成功済みの宛先はDBに記録し、通常の再チェック・再起動では再送しない。送信成功直後のDB障害や通信タイムアウトなど、Discord側の成功を確認できない障害では再送が重複する可能性がある。
- 再接続時は永続化したチャンネル別カーソル以降の履歴を復元する。通知直前も対象チャンネルの履歴とリアクションを確認し、取得に失敗した場合は通知を保留する。通常時は全チャンネルを定期クロールしない。

## 本番導入

`npm run db:migrate` でmigration 57を適用する。既存のpostinstallでも実行される。追加環境変数は不要。

Botには対象チャンネルの閲覧・履歴閲覧と管理用チャンネルへの投稿権限が必要。ロールを通知可能にする権限/設定も確認する。既存Message Content Intentに加え、コードでGuildMessageReactionsと部分イベント受信を有効化している。

常時稼働のRenderインスタンスを使用する。初回の実通知・リアクション・スタッフ返信・再起動後の復元は、本番接続した状態で確認すること。ローカルテストでは実際のDiscordへの通知を送らない。
