# Discord未返信アラート

既存BotのGatewayイベントで監視し、返信待ちの投稿ID・日時をPostgreSQLに保存する。本文・添付ファイルは保存しない。初回導入前の投稿は通知対象にしない。

- 生徒のユーザーID・通常チャンネルは一斉送信と同じスプレッドシートから取得する。生徒・Tutor・スタッフの対応表は1時間キャッシュする。
- 生徒の全投稿を対象とし、夜間・休日を含む12時間経過後、5分間隔のチェックで通知する。追加投稿は既存投稿の期限を延長しない。
- ユーザー管理に登録済みのスタッフ（契約解除を除く）の通常投稿は、同じチャンネルのそれ以前の返信待ちを解除する。スタッフ判別にはDiscordユーザーIDの登録が必要。Bot投稿は解除しない。
- リアクションは付いた投稿だけを解除する。誰のリアクションでも対象。削除された投稿も解除する。
- 担当Tutorにはユーザー管理のDiscord Webhookへ本人メンション付き、管理用チャンネル `1557730694166351912` にはロール `1294923221107478571` のメンション付きで通知する。Tutor設定が不足した場合も管理側へ通知し、Tutor側は設定修復後に再試行する。
- 成功済みの宛先はDBに記録し、通常の再チェック・再起動では再送しない。送信成功直後のDB障害や通信タイムアウトなど、Discord側の成功を確認できない障害では再送が重複する可能性がある。
- 再接続時は永続化したチャンネル別カーソル以降の履歴を復元する。通知直前も対象チャンネルの履歴とリアクションを確認し、取得に失敗した場合は通知を保留する。通常時は全チャンネルを定期クロールしない。

## 本番導入

`npm run db:migrate` でmigration 57を適用する。既存のpostinstallでも実行される。追加環境変数は不要。

Botには対象チャンネルの閲覧・履歴閲覧と管理用チャンネルへの投稿権限が必要。ロールを通知可能にする権限/設定も確認する。既存Message Content Intentに加え、コードでGuildMessageReactionsと部分イベント受信を有効化している。

常時稼働のRenderインスタンスを使用する。初回の実通知・リアクション・スタッフ返信・再起動後の復元は、本番接続した状態で確認すること。ローカルテストでは実際のDiscordへの通知を送らない。
