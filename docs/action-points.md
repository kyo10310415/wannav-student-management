# アクションポイント

生徒の旧レッドリストを置き換える。Tutorレッドリストは変更しない。
アクティブの生徒全員が対象。既存5項目を残し、アンケートを統合、集団レッスン参加を加え計16項目。
各項目は0/1Pt。評価済み項目数だけを分母にし、60%以上はレッド、30%以上はイエロー、それ未満はグリーン。
未取得・判定不能・対象外は加点せず分母にも含めない。分母0は判定不可。
各項目の定義は `src/services/actionPointRules.js` にまとめ、画面の詳細に同じ定義・理由・根拠リンクを表示する。

## 保存・更新

- マイグレーション60・61で `action_point_results` と `action_point_tutor_snapshots` を追加する。通常起動は全体マイグレーションを実行しないため、一覧・評価・月末保存・X取得の初回利用時に、この機能の4テーブルだけを確認し、不足分をCREATE TABLE IF NOT EXISTSで作成する。月末スナップショットを含む既存テーブルが揃っている場合はDDLを実行しない。初期化に失敗した場合は次の利用時に再試行する。
- 日次0:00 JSTに更新。画面の「データ更新」はバックグラウンド実行を開始し、実行中は画面が10秒間隔で再取得する。新規機能の結果が未作成の生徒は未評価で表示する。
- 同一プロセス内で一斉更新を重複実行しない。学生別に逐次処理し、会話全文を全学生分保持しない。
- Discord/AI/YouTubeの結果は24時間再利用する。手動更新でその期限は延長しない。日次更新時刻のずれで24時間未満の場合は翌回更新となる。
- Discordは最大2,000件/生徒/30日、AI入力は最大100,000文字。超過は一部だけで評価せず未取得にする。
- 再起動で実行中ジョブは停止する。保存済み結果は残り、再度データ更新または次の日次実行で続行できる。実行状態はプロセス内のみ。
- 当月10日以降の初回の予約不足判定は固定する。10日以前の導入・計算不能期間を遡って推測しない。
- 前月末のTutorを最終日23:59 JSTに保存する。履歴がない月を翌月の担当で補完しない。未設定→初回割り振りは加点なし。担当が現在未設定なら対象外。
- 旧重み付きの過去履歴は変更しない。新方式の詳細は月別JSONとして保持する。対応状況・担当者・送信管理は既存テーブルを引き続き使用する。EXの過去データは保持するが新評価の色には使わない。
- 満足度は学籍番号・年月で照合して当月の最新回答を使う。前月の実施者に対する満足度アンケート未回答だけを1項目として数える。
- レッスン実施率は前月の実施済み報告回数÷2。前月開始のない生徒は対象外。新規生徒の14日窓は開始から14日経過するまで対象外。

## 動画教材DB

中央管理アプリのRenderに `LEARNING_DATABASE_URL` を設定する。既存の `DATABASE_URL` は変更しない。
WannaV_EPと同じワークスペース・リージョンのInternal Database URLを利用可能。
接続は最大1本、接続10秒・クエリ15秒でタイムアウト。読み取り専用の接続設定を使用する。
専用DBユーザーに次の必要列だけSELECT権限を付与することを推奨する。

- users: id, role
- student_profiles: user_id, notion_page_id
- notion_students: notion_page_id, student_number
- user_progress: user_id, last_watched_at

ログインIDは変更可能なので `users.username` を照合キーにせず、プロフィール経由の `notion_students.student_number` を使う。
同じ学籍番号に複数アカウントが対応する場合は集計対象から外し未取得にする。
アカウントあり・履歴なしは14日間視聴なし。接続失敗・照合不可は未取得で、0件とは区別する。
最終視聴日時は教材閲覧・視聴進捗・クイズ操作でも更新され得る既存の日時であり、厳密な動画再生時間ではない。

## AIとSNS

- 既存 `OPENAI_API_KEY` を使用。任意の `OPENAI_ACTION_POINTS_MODEL`、未指定時は `OPENAI_QUALITY_MODEL` / `OPENAI_MODEL` / gpt-4o-miniの順。
- チャット内容が外部AIに送られる。本文・APIキー・接続URLをログには記録しない。モデルには会話内指示を無視させ、根拠IDは取得済みの本人発言と照合する。
- 投稿数が2件未満ならAI呼び出しせず判定不能。API失敗・無効な出力・会話不足も判定不能とし、課金/通信失敗で生徒の加点を増やさない。
- Xは `X_BEARER_TOKEN`、YouTubeは `YOUTUBE_API_KEY` を中央管理アプリにも設定すると公開活動を取得する。他アプリの環境変数は自動共有されない。未設定/権限不足/取得失敗は未取得。
- Xは本人タイムライン（返信・リポストを含む）、YouTubeは公開アップロード一覧で判定。非公開・削除された活動や非公開の配信履歴は把握できない。
- わなみさんは既存Q&A記録のA列日時・O列学籍番号を利用する。ミッションは実績未連携として未取得、集団レッスン参加は下記の2アンケートを使用する。

## 検証と本番確認

自動テストはモックを使用し、本番DBの書き込み・AI課金・Discord送信は行わない。
デプロイ後は初回のテーブル初期化が成功することを確認し、管理者/リーダーで「データ更新」を実行する。
学籍番号が分かる生徒の動画最終視聴、レッスン報告、AI根拠リンクを実データと照合する。
最初の月末保存前は担当変更項目が未取得になる。接続に失敗した場合はDBユーザーの権限・接続先・TLS設定を確認し、TLS検証を無効化しない。

## X APIの費用抑制

Xは日次の評価時に保存結果を確認するが、外部API取得はアカウントごとに最短7日間隔。
`action_point_x_cache` は月をまたいで保持し、同一アカウントを複数生徒が使う場合も共用する。
数値ユーザーIDを保存するので、通常は初回だけユーザー情報を取得する。登録ユーザー名の変更は別アカウントとして再取得する。
投稿のcreated_atも保存し、直近14日以内の投稿が既に確認できている間は週次の投稿取得も省略する。
投稿が14日窓から外れ、前回取得から7日以上経過した段階で再確認する。
7日以内は前回取得時の判定を使うため、新しい投稿の反映には最大約1週間かかる。
失敗した取得も試行日時を保存して7日間再試行を抑止し、取得失敗は未取得として分母から除外する。
UIのX項目に取得確認日時と保存済み最終投稿日時を表示する。手動更新や月替わりでは間隔をリセットしない。
APIの最小取得件数に合わせ投稿は最大5件のままとし、直近14日に投稿があるかの確認だけに使用する。

## 一覧の絞り込み

ステータス・契約プランで今月/過去月の一覧を絞り込める。初期値は「アクティブ」「永久会員以外」。
「すべて」または個別のステータス・契約プランに切り替えられる。空欄プランは永久会員以外に含める。
過去月は月末固定記録があれば保存時点の生徒情報を、未固定の場合は現在の生徒登録情報を使用する。表示件数・集計カード・CSVは同じ絞り込みを適用する。
自動再取得でも選択条件は維持する。読み取りAPIは全ステータスを返すが、評価対象は従来どおりアクティブのみであり、絞り込み変更で評価・外部API取得は行わない。

## 月末固定保存と生徒別推移

毎月最終日23:59 JSTに、その時点の当月評価をaction_point_monthly_snapshotsに固定保存する。
生徒名・担当Tutor・ステータス・契約プラン・評価日時・保存日時も保存する。同じ生徒・年月は再実行でも上書きしない。
外部APIやAIを追加実行せず、最後に計算・保存できた評価を使う。未評価のアクティブ生徒は未評価として記録する。
過去の年月指定では固定保存があればその月の固定記録だけを表示する。未固定の月は最終評価、導入以前は旧レッドリスト履歴を表示する。
固定保存のある月の絞り込みは保存時のステータス・契約プランを使用する。未固定/旧方式は現在の登録情報を使う。
生徒管理の「推移」から本人の月別加点数・評価済み項目数・割合・色・項目別根拠を確認できる。
月末のプロセス停止等で実行できなかった場合、存在しない月末状態を翌月の登録情報から推測して作成しない。評価結果自体は残るため未固定の最終評価として参照可能。

## 更新時間

現在は1人ずつ順にDiscord履歴、AI、SNSを取得して保存する。初回や24時間キャッシュ失効時はその待ち時間が人数分累積する。
Discordは最大20ページ/人、AIは最大60秒、X/YouTubeの各リクエストも通信待ちがあり、履歴の量やAPI応答によって時間が変わる。
Xの最短7日間隔と確認済み投稿による省略は維持する。今回、取得頻度の増加・一斉並列化は行わない。
画面に処理済み件数・全体件数・現在の処理段階を表示する。これらはプロセス内の進捗で、サーバー再起動後は再更新が必要。
本番の実所要時間・段階別時間は未計測。コード上の通信待ちをボトルネック候補として説明している。
