# VQ診断通知システム セットアップガイド

## 概要

VQ診断結果をGoogle スプレッドシートから自動的に取得し、生徒様のDiscordに送信するシステムです。

## システム構成

```
Google スプレッドシート (VQ診断結果)
         ↓
Google Apps Script (GAS)
         ↓
Webhook API (サーバー)
         ↓
PostgreSQL Database
         ↓
Discord Webhook (生徒様のチャンネル)
```

## 1. データベースマイグレーション

Render にデプロイすると、`postinstall` スクリプトで自動的にマイグレーションが実行されます。

マイグレーションファイル：
- `migrations/20260327_add_vq_diagnosis_notifications.sql`

作成されるテーブル：
- `vq_diagnosis_notifications`: VQ診断の送信履歴を記録

システム設定：
- `system_settings` テーブルに `vq_diagnosis_notification_enabled` が追加されます（デフォルト: `false`）

## 2. Google Apps Script (GAS) セットアップ

### 2.1 スプレッドシートを開く

https://docs.google.com/spreadsheets/d/1_yJtJn8DMFkQBtdIkDWHNBE8-kpHyE3-0FY_oe0EhJ0/edit

### 2.2 GAS エディタを開く

1. スプレッドシートのメニューから「拡張機能」→「Apps Script」を選択
2. 新しいGASプロジェクトが開きます

### 2.3 スクリプトファイルを作成

1. 左側の「ファイル」セクションで「+」ボタンをクリック
2. 「スクリプト」を選択
3. ファイル名を `VQDiagnosisSync` にする
4. `/home/user/webapp/gas-vq-diagnosis-sync.js` の内容をコピー＆ペースト

### 2.4 Webhook URL を設定

スクリプトの `CONFIG` セクションで `WEBHOOK_URL` を設定：

```javascript
const CONFIG = {
  SHEET_ID: '1_yJtJn8DMFkQBtdIkDWHNBE8-kpHyE3-0FY_oe0EhJ0',
  SHEET_NAME: '診断結果',
  WEBHOOK_URL: 'https://wannav-student-management.onrender.com/api/vq-diagnosis/process', // ← あなたのサーバーURLに変更
  // ...
};
```

### 2.5 トリガーを設定（自動実行）

#### 方法1: スクリプトから設定（推奨）

1. GASエディタで関数 `setupDailyTrigger` を実行
2. 初回実行時、権限の承認が必要です：
   - 「権限を確認」をクリック
   - Google アカウントを選択
   - 「詳細」→「（プロジェクト名）に移動」をクリック
   - 「許可」をクリック

これで毎日午前9時に自動実行されます。

#### 方法2: 手動でトリガーを設定

1. GASエディタの左側メニューで「トリガー」（時計アイコン）をクリック
2. 右下の「トリガーを追加」をクリック
3. 以下のように設定：
   - 実行する関数: `syncVQDiagnosisResults`
   - イベントのソース: `時間主導型`
   - 時間ベースのトリガータイプ: `日タイマー`
   - 時刻: `午前9時～10時`
4. 「保存」をクリック

### 2.6 手動テスト実行

トリガー設定前に、手動でテストすることをおすすめします：

1. 関数 `testLoadVQData` を実行
   - スプレッドシートからデータが正しく読み込まれるか確認
   - 実行ログで診断結果の件数と内容を確認

2. 関数 `syncVQDiagnosisResults` を実行
   - サーバーに送信されるか確認
   - 実行ログで送信成功/エラーを確認

### 2.7 トリガー管理

#### トリガー一覧を表示
```javascript
listVQTriggers()
```

#### すべてのトリガーを削除
```javascript
deleteAllVQTriggers()
```

## 3. アプリケーション側の設定

### 3.1 VQ診断システムを有効化

1. ブラウザで管理画面を開く
2. ヘッダーの「VQ診断」ボタンをクリック
3. 右上の「システム」トグルを **ON** にする

### 3.2 生徒のDiscord URLを確認

VQ診断を送信するには、各生徒の `discord_url` が設定されている必要があります：

1. 「生徒管理」ページで生徒を選択
2. 「Discord」列にURLが設定されているか確認
3. 未設定の場合は編集して追加

## 4. 動作確認

### 4.1 GASの実行ログを確認

GASエディタで「実行数」をクリックすると、過去の実行履歴とログが見られます：


### 4.2 アプリケーションで送信履歴を確認

1. 「VQ診断」ページを開く
2. 「送信履歴」セクションで以下を確認：
   - 送信日時
   - 生徒名
   - 合計点
   - 診断タイプ
   - 状態（送信済み / エラー）

### 4.3 Discordで通知を確認

生徒のDiscordチャンネルに以下のようなメッセージが送信されます：

## 5. エラー対応

### エラー: 「システムがOFFです」

- アプリケーション側で「VQ診断」ページのトグルが **OFF** になっています
- トグルを **ON** にしてください

### エラー: 「生徒が見つかりません」

- スプレッドシートの生徒名とデータベースの生徒名が一致していません
- 生徒管理ページで正しい名前を確認してください

### エラー: 「Discord URLが設定されていません」

- 該当生徒の `discord_url` が未設定です
- 生徒管理ページで Discord URL を設定してください

### エラー: 「サーバーエラー: 500」

- サーバー側でエラーが発生しています
- Render のログを確認してください

### 再送信機能

エラーが発生した場合、修正後に「VQ診断」ページから再送信できます：

1. 送信履歴でエラーのレコードを探す
2. 「再送信」ボタンをクリック
3. 確認ダイアログで「OK」をクリック

## 6. 重複送信の防止

同じ生徒に対して、同じ診断タイプの結果を30日以内に複数回送信することを防ぎます。

スプレッドシートに新しい診断結果が追加されても、既に送信済みの場合はスキップされます。

## 7. メンテナンス

### システムの一時停止

長期間使用しない場合は、システムを **OFF** にしてください：

1. 「VQ診断」ページを開く
2. 右上のトグルを **OFF** にする

これにより、GAS が実行されてもサーバーは処理をスキップします。

### GAS トリガーの削除

完全に停止する場合は、GAS のトリガーも削除してください：

```javascript
deleteAllVQTriggers()
```

## 8. トラブルシューティング

### Q: GASの実行が失敗する

A: 以下を確認してください：
- スプレッドシートIDが正しいか
- シート名「診断結果」が存在するか
- Webhook URLが正しいか
- サーバーが稼働しているか

### Q: Discordに送信されない

A: 以下を確認してください：
- システムトグルが **ON** になっているか
- 生徒の Discord URL が正しいか
- Discord Webhook URLが有効か

### Q: 送信履歴が表示されない

A: データベース接続を確認してください：
- Render のログでエラーがないか確認
- データベース URL が正しく設定されているか確認
