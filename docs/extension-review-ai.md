# 延長審査AI採点

既存のNode.js/Hono/Vanilla JS/PostgreSQL内に追加した独立機能。別アプリ・Renderサービス・ログイン基盤は作らない。既存の延長審査DB、満足度、回収率、Tutor品質評価に書き込まない。

## 実装と影響範囲

- API: `/api/extension-review`。既存sessions/usersのBearerセッションで毎回認証し、admin/leaderのみ許可。crewは全API拒否。
- UI: 「延長審査AI採点」の6タブ（実行・結果・履歴・Tutor分析・基準管理・接続診断）。Tutor管理に独立した分析へのリンクを追加。
- 実行入力: 審査回数1〜4、**実際の実施Tutor**、Notion生徒ページURL、Google Docs URL。登録済みのアクティブTutorから選択し、当時の識別情報を結果に保存する。
- 文字起こしの発言者ラベルを実施Tutorの登録名/Notion名/氏名/管理者登録別名と照合する。本人を特定できなければOpenAIを呼ばず停止し、採点結果にも本人の発言根拠が最低1件あることを検証する。別名は基準管理で後から登録・修正できる。
- 新規migration 58: `extension_review_settings`、`extension_reviews`、`extension_review_edits`。追加型・IF NOT EXISTS。既存テーブルのデータ/カラムは変更しない。users/tutors/studentsへの新しい外部キーによる既存削除操作の制約も追加しない。
- `driveService.js`の既存認証とタブ展開を再利用し、新規`fetchReviewTranscript`を追加。既存`fetchTranscript`のタブ選択・フォールバック・議事録生成は変更しない。
- `notionService.js`に専用読み取りクライアントの取得関数を追加。既存の学生用認証を再利用し、SDKログを抑止。既存同期クライアント・再試行処理は変更しない。
- OpenAI公式SDKと既存OPENAI_API_KEYを使用。専用クライアントはmaxRetries=0、timeout=90秒、logLevel=off。議事録のクライアント/モデル設定は変更しない。
- 機能用テーブル以外への書き込み、既存APIレスポンス変更、認証仕様変更、自動ジョブ追加・変更、依存ライブラリ更新はない。

## 有効化・登録手順

1. 管理者がPRをレビューし、検証環境でmigration 58・既存画面の起動を確認する。実行には既存のmigration手順を使う。
2. 承認後に反映し、最初はflag=falseのまま既存機能を確認する。
3. 管理者がflag=trueへ変更し、ブラウザーを再読込する。**基準・対象スクリプト・単価が未登録なら採点は拒否される**ため、この時点で採点API料金は発生しない。
4. 管理者の「API接続診断」でNotion/Docs URLを指定し、プロパティ名・型・本文見出し、ドキュメント共有、指定モデルの利用権限を確認する。診断はモデルの取得のみで、Responses採点は実行しない。
5. NotebookLMで使っていた採点基準と、必要な1〜4回目のスクリプトを登録する。架空の初期基準は登録しない。後から追記・修正でき、保存は新しいバージョンとして履歴に残る。
6. Notion項目マッピング、必要に応じTutor発言者別名（Tutor番号→文字起こし表記の名前配列）、公式単価を登録し、テスト用の資料で採点・引用照合・Markdown・確認/確定・履歴を確認する。
7. 実施TutorとNotion/Docs間の生徒対応を人が確認して利用する。モデルに生徒の採用/契約継続などの意思決定を自動実行させない。

この開発では本番設定変更・マージ・デプロイ・実採点を行わない。

## Notion項目マッピング

```json
{
  "streams": {"source": "property", "name": "やってみたい配信"},
  "age": {"source": "property", "name": "生年月日", "transform": "ageFromBirthDate"},
  "companyReasons": {"source": "property", "name": "企業が良い理由"},
  "expenseConsent": {"source": "property", "name": "実費負担への合意"},
  "classification": {"source": "property", "name": "6分類"}
}
```

propertyはtitle/rich_text/number/checkbox/select/status/multi_select/date/formula/rollup/relationの型を解析する。本文は子ブロック・ページネーションに対応。relationは関連ページのタイトルを解決する。生徒ID/名前は既存の学籍番号/名前プロパティと登録済みstudentsのNotionページIDを照合し、不一致・複数候補・未登録なら停止する。

CSVのヘッダーに合わせた上記マッピングを標準とする。未設定（空オブジェクト）の場合も標準を使う。既存の明示的なカスタム設定は上書きしないため、基準管理の「CSVに合わせた標準マッピングを入力」を押し、新しいバージョンとして保存する。

年齢は生年月日と取得当日の日本時間の日付から満年齢を計算する（誕生日当日に加齢、2月29日生まれは平年の3月1日に加齢）。YYYY-MM-DD、YYYY/M/D、Notionの日付型のISO日時に対応し、空欄・不正・未来日付・120歳超は不明とする。数値の年齢を取得する既存カスタム設定は互換維持する。保存する人物像は計算した年齢のみで、生年月日の原文を保存しない。企業がいい理由は明示的なリスト・件数・箇条書きだけを数え、通常の自由文を句読点だけで意味的に分割しない。Notion本文は最大20階層/2000ブロック、relationは項目ごとに50件、保存対象の各人物像項目は20000文字まで。取得全体は100リクエストまでとし、ページネーションの循環も検出する。上限超過は黙って切り捨てず停止する。

ターゲット条件のキーワード・年齢範囲・理由数・Yes/No表記はadminが編集できる。初期条件は依頼の6条件のみ。判定はJavaScriptで行い、一致/不一致/不明を保持する。1件でも不明なら全6条件の一致率はnull（算出不可）とし、確認済み条件の一致件数を別表示する。既存の審査成否やTutorスコアにターゲット一致率を自動加算しない。

## Docs・採点・根拠

### 前後の文脈と引き留めの評価

発言者・時刻の検証は原文の発言境界と時刻マーカーから構築した区間を使い、引用周辺の固定文字数に依存しない。本文の「補足：」「注意：」「例：」「参考：」「備考：」は発言者ラベルから除外する。MM:SS/HH:MM:SSは秒数で照合するが、原文の引用は完全一致を維持し、別人への帰属・誤った時刻は拒否する。対応形式は行頭の「発言者:」または「発言者：」、独立行の時刻（角括弧可）。未対応形式を推測して通さない。

API失敗は残高/課金上限、認証、モデルアクセス、レート制限、タイムアウト、上流障害を区別して表示する。Renderログの`[ExtensionReview]`には処理段階、固定の分類、HTTPステータスのみ記録し、SDKエラー全文・キー・資料URL・本文・人物像を記録しない。検証失敗も同じ安全なログ形式を使用する。時間上限と月間上限は別メッセージで件数を表示し、上限値・失敗を含むカウント・自動再試行しない仕様は維持する。議事録サービスの処理や、OpenAIの残高設定は変更しない。

評価方針context-v2では全文を時系列で確認し、単語・一文だけで成果の否定や圧力と認定しない。辞退・迷いがある場面は「理由を深掘り→不安の払拭や解決策の提示→再度意思確認」という機能を評価し、引き留め・継続提案そのものは減点しない。一方で、理由への対応がない・確定した意思を無視する等の課題を免責しない。文脈依存の評価は原則2〜4件の原文引用を時系列で提示し、説得意図・表現上の懸念・実際に確認できた対応を分けて説明する。不明な反応や成果は断定しない。

登録基準・配点、対象回の登録スクリプト、モデル、推論設定、API回数、JSON形式は変更しない。添付された2回目台本は評価方針を検討する参考として読み、システムの登録スクリプトを勝手に置き換えない。評価方針バージョンを再利用ハッシュに含めるため、更新後の採点開始では旧方針の結果を再利用せず別結果として採点する。既存結果の自動再採点・上書きは行わない。プロンプト・保存のモックテストと実AIの評価精度は区別し、実例での新しい判定は人が確認する。

- HTTPSのNotion/Google Docs正規ホストとIDだけを受け付ける。任意URLをHTTP取得せず、SDKの固定APIへIDでアクセスする。userinfo/独自ポート/類似ドメインは拒否する。
- Docsは全タブを再帰展開し、文字起こしタブとその子タブを優先。該当なしなら全タブを読む。テーブル内の本文も再帰抽出し、発言者・時刻・原文を保持する。
- 通常はResponses API 1回。Structured OutputsでJSONを取得し、ローカルで0〜100の範囲、必須構造、原文完全一致引用、付随する発言者/時刻を検査する。曖昧・未完了・拒否・不正JSONは採点成功として保存しない。
- 意味の評価まで機械的に証明するものではない。人が引用・生徒意向・スクリプトとの差と対応品質を確認する。AI一次評価は保存後も維持し、管理者編集は別JSONと編集履歴へ保存する。
- leaderは実行/閲覧/確認、adminは加えて基準編集/結果編集/確定/診断。確定済みはAPI側で編集拒否し、再採点は別レコードを作る。
- 文字起こし全文をDBへ保存しない。保存するのはハッシュ、人物像スナップショット、結果と限定された根拠引用、ID、基準版、モデル、usage、推定料金、操作者・確認情報。
- 出力テンプレートは`{{grading}} {{script}} {{profile}} {{factors}}`をすべて使用。空欄では延長審査採点、トークスクリプト（太字ラベルの一致度・オリジナリティ）、生徒様の人物像（太字の一致率と5項目）、要因分析（■ 良かった点・課題点・総括）の4セクションを区切り線付きで出力する。要因分析の根拠引用は保持する。設定済みのカスタムテンプレートは配置を維持し、各セクションの書式が更新される。保存済み結果のMarkdownは変更しない。MarkdownはJS生成で、UIではエスケープして表示する。
- SDKエラー/資料内の命令をシステム指示にしない。モデル自動切替・自動再採点・無制限再試行はない。

## 運用

コスト関連の画面表示（結果・履歴・Tutor分析）と単価入力欄は削除した。単価未登録でも採点でき、新しい設定の保存時には単価をnullとする。既存設定・DB・APIとの互換性のため内部のusage/料金フィールドは残す。以下の単価計算説明は過去設定に対する内部処理であり、利用者による単価登録は不要。採点APIの課金自体は継続し、再採点確認・件数上限・同時実行制限は維持する。

- 指定回のスクリプトのみ送信。固定の基準/スクリプトをプロンプト先頭に置き、サービス側の自動Prompt Cachingを利用可能な形にする。人物像・Notion本文はモデルへ送らず、必要な文字起こしだけを送る。
- 資料内容・人物像・実施Tutor・回数・基準版・モデルのハッシュが同じなら保存済み結果を返し、OpenAIを呼ばない。再採点は確認必須。
- 30リクエスト/ユーザー/分、採点10件/ユーザー/時間、設定可能な月間件数上限（初期100）。DB advisory lockで同時採点は1件。通常の既存機能をロックするものではない。
- 文字起こしの初期上限100000文字、出力上限6000token。上限超過は採点せず、AIが未完了なら停止する。
- 単価は管理設定でUSD/100万tokenを登録する。`input`、`cachedInput`、`output`、必要に応じ`cacheWrite`、`longThreshold`、`longInput`、`longCachedInput`、`longOutput`、`longCacheWrite`。単価未登録では実行しない。長文単価が必要だが未登録の場合の料金は未算出となる。
- 公式モデル仕様: https://developers.openai.com/api/docs/models/gpt-6-sol 。Responses/Structured Outputs対応は確認済み。アカウントでのモデル利用可否は別途診断する。単価を実装へ固定しない。
- 月間利用量は採点実行レコードから入力/出力/キャッシュtoken、件数、失敗件数、推定料金、未算出件数を集計する。前処理エラー・接続診断は採点API件数に含めない。
- SDKからusageが得られた失敗も保存する。usageなしの失敗/中断は無料と仮定せず、料金未算出とする。個別加算/税/リージョンなどはこの推定に含まれず、請求額の保証ではない。
- タイムアウトやブラウザー切断時はまず履歴を確認する。pendingは処理中または中断の可能性があり、自動再試行しない。完了済みなら履歴から再表示し、再採点による追加料金を避ける。
- Tutor分析は基準版が異なる結果や管理者編集結果を含むことを表示し、減点/改善頻度は同一文言で集計する。既存指標への自動加算はない。
