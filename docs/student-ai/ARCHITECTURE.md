## 暫定推奨: 段階的ハイブリッド（案Aを検証候補とする）

T005未完了につき方式は未確定。PostgreSQLで質問意図に応じて候補を変える案を先に評価する。T005で件数・文字量・欠損率を測定し、T010で精度・費用・速度を比較して最終確定する。T030/T090開始前にinventory結果と設計を再報告する。T015のみinventory非依存で先行可能。

理由は、既にminutesへ要約と構造化品質評価があり、外部Vector Storeへ個人情報を複製せず短期間で安全性を検証できるため。単なる最新N件固定にはしない。

## リクエストフロー

1. UIが選択済みstudent IDと質問を送信。
2. `requireAuth` がsessionを検証しuserをcontextへ格納。
3. studentの存在を確認。
4. 質問をルールベースで `latest` / `previous_goal` / `period_compare` / `longitudinal` / `repeated_issue` / `topic` に分類。
5. 必ず `student_id = $1` を条件に候補を取得。
6. 日付と要約による一次選抜後、上限内のtranscript断片を構築。
7. system promptで資料と命令を分離し、JSON回答を生成。
8. サーバーが引用ID/日付を照合し、回答＋sources＋usageを返す。

## 検索戦略

| 意図 | 取得方針 |
|---|---|

| 前回目標 | 直近2件、next_action/qualityを優先 |

| 長期成長 | 全期間軽量情報を俯瞰→意味的重要度で候補選択→候補原文を確認。固定代表1件方式は採用しない |
| 繰り返し課題 | 全期間の要約をテーマ検索し、異なる3時点以上を優先 |

## API案

`POST /api/student-ai/:studentId/questions`

Request: `{ "question": "..." }`

Response: `{ success, data: { answer, evidence, changes, recommendedActions, confidence, sources: [{ minutesId, lessonDate, tutorName, driveUrl }] } }`

student IDはUI入力欄を設けず、開いたカードの内部値を使う。ただしサーバーはURL値を信用せず、存在・長さ・形式を検証する。

## 長期検索: 二段階方式の比較と評価

第一段階では選択student_idの全期間metadata/generated_text/quality_evaluationをDBからページ単位で列挙する。DBでの全件走査と、全件を一度のAI入力に送ることは別である。質問と関連する課題・目標・改善・後退・矛盾・転機を選び、各候補のsource IDと日付を保持する。

第二段階で候補sourceだけtranscriptの関連箇所を取得し、周辺文脈と最新の反証を確認して回答する。原文抜粋にはsource IDと文字位置を保持し、引用を実原文に照合する。

| 方式 | 利点 | 取りこぼし/対策 |
|---|---|---|
| 機械的な時期サンプリング | 安価、時系列を広くカバー | 各期の代表外の転機を失う。補助的coverage確認に限定 |
| 全軽量情報から意味的重要度選択 | 質問に重要な転機・反復課題を選べる | generated_text自体の情報欠落がある。選択候補の原文確認と検索評価が必要 |
| 月/四半期の階層要約＋意味選択 | 入力上限超過時に全期間を扱える | 要約で情報が消える。根拠IDを保持し、子要約/原文へ遡れる設計 |

入力上限超過時はtoken予算内で月単位に分割し、必要なら四半期→全期間へ階層化する。各階層に複数の重要事項・根拠ID・矛盾を残し、1期1件に制限しない。期間ごとの処理済み範囲と未処理範囲も記録し、一部しか見ていない場合に全期間確認済みと回答しない。複数回AI選択のtoken費用も計測する。

固定サンプリングでは落ちる中間時点の重要レッスン、後日の改善/反証、古い反復課題を含む正解セットで、候補再現率・引用正確性・遅延・費用を比較する。意味選択＋階層化を暫定推奨するが、取りこぼしゼロは保証せず、T005後に受入水準を決めてT010で確定する。

## データモデル方針（T005後確定）

既存minutesをPrimaryとする。過去レッスン番号欠損・同日複数Docsを安全に保持する候補として、AI専用sourceテーブルを追加し、簡易要約を作るC+Bを暫定推奨する（BACKFILL_PLAN参照）。既存minutesのstudent+date唯一制約とUPSERTは即時変更しない。同一Drive文書はminutesを優先して二重引用を防ぐ。専用sourceとの統合も必ずstudent条件を適用する。

## 品質ゲート

固定質問セットと、他生徒固有のカナリア語を使った分離テストを用意する。長期質問で複数時点を引用できない場合のみpgvector PoCへ進む。
