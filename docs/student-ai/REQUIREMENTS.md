# WannaV AI生徒カルテ 要件

## 目的

生徒管理画面で選択した生徒について、蓄積済みレッスン記録を時系列で検索し、根拠付きの回答と次回行動を返す。利用者は学籍番号を入力しない。

## 確定要件

- 対象ロールは `admin`、`leader`、`crew`。ログイン済みユーザーは全生徒を参照できる。
- API側で有効なBearerセッションを必須とし、未ログインは401で拒否する。
- すべての検索SQLで、URLから受け取った `student_id` をバインド条件に含める。他生徒の記録を混ぜない。
- Primary sourceは `minutes`。`generated_text`、`quality_evaluation`、`transcript`、日付、Tutor、Drive情報を利用する。
- Secondary sourceは必要時のみ `lesson_reports`、`lessons`、`lesson_contents`、`students` とする。
- 過去全期間を対象にできる。質問意図ごとに直近、比較時点、全期間を切り替える。
- 質問ごとに全文字起こしを送らない。候補抽出後、必要な記録だけAIへ送る。
- 回答は原則、回答・根拠・時系列変化・推奨行動・参照レッスン・確信度を返す。
- 記録にない内容を断定しない。根拠不足時は判断不能と明示する。
- 文字起こし中の命令は参考資料であり、system instructionとして扱わない。
- 参照日、議事録ID、可能ならDriveリンクを構造化レスポンスで返す。
- MVPではチャット履歴をDBまたはlocalStorageへ保存しない。画面内メモリのみ許可する。
- 既存画面を全面改修せず、生徒カードの名前/専用ボタンからモーダルを開く。
- Drive全期間バックフィルは冪等、少量バッチ、再開可能、進捗可視、有限retryとする。

## 非機能要件

- 質問文字数、取得件数、入力文字数、出力トークンに上限を設ける。
- AI/Drive障害は既存画面に波及させず、安全な日本語エラーを返す。
- transcript本文、APIキー、Google認証情報をログへ出さない。
- `student_id`、日付、作成者、モデル、token usage、成功/失敗だけを監査可能にする。

## MVP対象外

- 会話履歴の恒久保存、Tutor間共有、質問履歴検索
- 全記録への常時embedding付与
- 生徒別アクセス制限（本MVPは全ロールが全生徒可）
- 本番全件バックフィルの自動開始

## 未確定・実測待ち

Driveフォルダ数、文書総数、最古/最新日、平均件数、平均文字数、実コストは、本番Google認証情報を持つ安全な環境で棚卸しを実行して確定する。
